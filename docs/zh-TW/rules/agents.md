# Agent 協調

## 可用 Agents

位於 `~/.claude/agents/`：

| Agent | 用途 | 何時使用 |
|-------|------|----------|
| planner | 實作規劃 | 複雜功能、重構 |
| architect | 系統設計 | 架構決策 |
| tdd-guide | 測試驅動開發 | 新功能、Bug 修復 |
| code-reviewer | 程式碼審查 | 撰寫程式碼後 |
| security-reviewer | 安全性分析 | 提交前 |
| build-error-resolver | 修復建置錯誤 | 建置失敗時 |
| e2e-runner | E2E 測試 | 關鍵使用者流程 |
| refactor-cleaner | 無用程式碼清理 | 程式碼維護 |
| doc-updater | 文件 | 更新文件 |

## Agent 使用政策

委派政策的正本為 `rules/common/agents.md`，本文件是其翻譯。

**機制。** 本規則說明何時適合委派，但不會自動啟動 Agent，執行環境也不會自行啟動。只有當父模型
呼叫可用的 Agent 或 Task 工具並回收其結果時，Agent 才會執行。

**期待。** 當該工具可用且更高優先權的指示允許時，請自行判斷是否委派。不需要使用者另外提出要求。

**優先順序。** 系統、執行環境或 harness、組織與使用者的更高優先權指示，永遠優先於本規則。當
harness 限制委派時（例如「除非使用者要求，否則不要呼叫 Agent 工具」），請遵循 harness。此時本
規則說明的是應涵蓋哪些觀點，而不是允許覆寫該限制。

當委派工具可用且更高優先權的指示允許使用時：
1. 複雜功能請求 - 考慮 **planner** Agent
2. 剛撰寫/修改程式碼 - 考慮 **code-reviewer** Agent
3. Bug 修復或新功能 - 考慮 **tdd-guide** Agent
4. 架構決策 - 考慮 **architect** Agent

當委派不可用或被禁止時，請將工作留在父內容中，並直接套用相同的規劃、測試與審查檢查清單。在沒有
呼叫工具並回收結果的情況下，絕不可宣稱 Agent 已執行。

## 平行任務執行

只有在執行環境允許委派，且父模型能於結束該回合前回收所有結果時，才對真正獨立的操作使用平行
Task 執行。禁止發出後不回收結果的委派：

```markdown
# 好：平行執行
平行啟動 3 個 agents：
1. Agent 1：auth.ts 的安全性分析
2. Agent 2：快取系統的效能審查
3. Agent 3：utils.ts 的型別檢查

# 不好：不必要的循序
先 agent 1，然後 agent 2，然後 agent 3
```

## 多觀點分析

對於複雜問題，當允許委派且各觀點確實互相獨立時，可考慮使用分角色子 agents：
- 事實審查者
- 資深工程師
- 安全專家
- 一致性審查者
- 冗餘檢查者

當委派不可用時，請在父內容中以個別回合執行相同的觀點。能抓出只看 diff 的審查所遺漏缺陷的是觀點
本身（例如 diff 只改動一行、但整段流程的步驟順序有誤）；Agent 只是載體。
